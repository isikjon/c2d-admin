**Публичный API Chat2Desk**

Этот API предназначен для отправки и получения сообщений, получения списка клиентов, применения тегов, установки веб\-перехватчиков и многого другого.

Чтобы начать тестирование API:

* Перейдите на сайт системы (см. *УСЛОВИЯ* ниже) под учетной записью администратора и откройте раздел *«Настройки» \> «API» .*  
* Используя приложение Postman, скопируйте токен API в эту коллекцию Postman в разделе *«Переменные»* .  
* Убедитесь, что у вас есть несколько сообщений от клиентов для тестирования API.

**УСЛОВИЯ**

*Система* — сервис [Chat2Desk](https://chat2desk.com/) .

*Клиент* — лицо, отправляющее или получающее сообщения через Систему.

*Транспорт* – мессенджер, социальная сеть или онлайн-чат, поддерживаемый Системой. Такие как WhatsApp, Viber, Telegram, Facebook, Instagram, ВКонтакте, онлайн-чат и многое другое.

*Канал* — группа ваших аккаунтов в мессенджерах. У вас может быть много каналов с разными автоматическими ответами, меню самообслуживания, назначением чата и т. д. для каждого канала.

*Внешний канал* — источник сообщений от любого мессенджера (транспорта), не поддерживаемого Системой. Например, сторонний чат, мессенджер, приложение или CRM.

*Запрос* — набор сообщений в рамках диалога с клиентом. Как правило, запрос начинается с первого сообщения клиента и заканчивается закрытием диалога. Когда клиент продолжает общаться в закрытом диалоге, в том же диалоге запускается новый запрос.

**ОБЩАЯ ИНФОРМАЦИЯ**

* Используются архитектура RESTful и методы GET, PUT, DEL и POST.  
* Результаты команд представлены в формате JSON.  
* Этот API использует HTTPS.  
* Авторизация основана на токене API, который доступен в разделе *«Настройки» \> «API»* на сайте под учетной записью администратора.  
* Команды, возвращающие большой список данных, поддерживают разбиение на страницы с использованием параметров URL:  
  * *предел* — количество возвращаемых записей (максимум — 200, по умолчанию — 20).  
  * *offset* — смещение от 1-й записи списка (по умолчанию 0). Messages (GET)является исключением, поскольку вместо *смещения используется start\_id* . Пример запроса (список клиентов):/v1/clients?offset=50\&limit=30  
* В целом система предназначена для ответа тем клиентам, которые впервые обратились в вашу компанию и значит находятся в списке ваших клиентов (см. clients (GET)). Используя clients (POST)вы можете создать нового клиента и затем связаться с ним или с ней. Свяжитесь с этими недавно созданными клиентами разумно, потому что ваша учетная запись мессенджера может быть **заблокирована** за спам в случае слишком большого количества новых контактов или сообщений.

**ПРЕЖДЕ ЧЕМ ВЫ НАЧНЕТЕ**

Получите свой токен API на сайте системы в разделе *«Настройки» \> «API»* . Информация об API доступна в формате api\_modes (GET). Поместите токен в эту коллекцию Postman в разделе *«Переменные»* с помощью приложения Postman.

Существует 2 способа работы с сообщениями:

* Ваши клиенты используют обычные мессенджеры, социальные сети, электронную почту или наш онлайн-чат для отправки сообщений в вашу компанию. В этом случае используйте webhooks (POST)для получения этих сообщений от системы. Для отправки сообщений обратно клиентам используйте messages (POST).  
  Если вы хотите связаться с клиентом, который никогда раньше с вами не связывался (это платная опция *«Написать первым»* ), используйте для создания нового клиента, получите идентификатор клиента, а затем используйте для отправки сообщения, как описано выше.client (POST)messages (POST)  
* Ваши клиенты связываются с вами через ваше собственное приложение, CRM или контактную форму, и вам нужна Система, чтобы ваши операторы (агенты) и чат-боты могли обслуживать клиентов. Вам следует использовать *внешний канал* для передачи сообщений в Систему из этих внешних источников сообщений с использованием messages/inbox (POST). Чтобы получать ответы операторов и чат-ботов и отправлять их обратно своим клиентам – используйте веб\-хуки (см webhooks (POST). ).

**ПОЛУЧАТЬклиенты**  
https://api.chat2desk.com/v1/clients/  
Возвращает список ваших клиентов с их информацией. Вы можете фильтровать список клиентов по телефону клиента, тегам, информации в информационной карточке клиента и т. д.

Некоторые поля в ответе:

* назначенное\_имя – имя, присвоенное клиенту – см. clients (PUT).  
* комментарий – комментарий клиенту, оставленный оператором на сайте.  
* custom\_fields – данные JSON настраиваемых полей вашего клиента с их идентификатором, именем и значением. Эти поля видны операторам в информационной карточке клиента. Они управляются администратором в разделе *«Настройки» \> «Общие»* на сайте.  
* телефон – номер телефона клиента, если он существует. Доступно только для WhatsApp, Viber, Viber Business, числового (пользовательского) Telegram и SMS. Для других мессенджеров сохраняется соответствующий идентификатор клиента этого мессенджера. Также см . *client\_phone* ниже. Для числового (пользовательского) Telegram телефон клиента хранится как *телефон \[tg\_user\],* например *\[tg\_user\] 11122233344* .  
* client\_phone — телефон клиента, если клиент раскрыл свой реальный номер телефона в мессенджерах, которые по умолчанию его не раскрывают (сейчас Telegram и Facebook). Также это поле может редактироваться оператором вручную или через clients (PUT).  
* name – никнейм клиента (если имеется).

### **ПОЧТАсообщения/импорт**

https://api.chat2desk.com/v1/messages/import/

Этот метод позволяет импортировать сообщения (входящие, исходящие, вложения), которых нет в системе C2D (если пользователь переписывался до подключения мессенджера в системе C2D).

Сообщения можно импортировать в виде массива, но отправлять можно не более 10 сообщений за один запрос.

В параметре приложения можно передать только одно вложение, а формат вложения представлен в виде прямой ссылки на файл.

В случае, если operator\_idне указан, автоматически подставляется id администратора, при этом после импорта диалог не будет переведен на админку.

##### **Параметры:**

**client\_id** — уникальный идентификатор клиента (обязательный параметр).

**Channel\_id** — канал, к которому подключено устройство (обязательный параметр).

**транспорт** — имя транспорта, для которого импортируются сообщения (обязательный параметр).

**timestamp** — дата отправки/получения сообщения, по которой сортируются все диалоговые сообщения (обязательный параметр).

**text** — текст сообщения, контекстно-зависимый от значения параметра Attachment:

* если вложение не заполнено \- обязательный параметр  
* если вложение заполнено \- заполнять необязательно

**Attachment** — массив с вложениями, контекстно-зависимый от текстового параметра. Если текст заполнен, параметр является обязательным. Если текст не заполнен, то он не требуется. Параметр должен содержать прямую ссылку на ресурс. В параметре приложения можно передать только одно вложение.

**type** - Тип сообщения (обязательный параметр). Возможные ответы "автоответ" "to\_client" "from\_client"

**operator\_id** — уникальный идентификатор автора сообщения, контекстно-зависимый параметр от значения параметра type (необязательный параметр):

* if type \= to\_client — если параметр не указан, идентификатор администратора компании будет присвоен автоматически.  
* если type=auto\_reply \- заполнение параметра не требуется

**external\_id** — если вы отправляете сообщение с использованием интеграции с другой платформой или CRM-системой, в этом поле вы можете сохранить идентификатор сообщения во внешней системе.

## **Меню самообслуживания**

## 

Работа с пунктами меню самообслуживания.

### **ПОЛУЧАТЬсценарии**

https://api.chat2desk.com/v1/scenarios/menu\_items

Возвращает список доступных пунктов меню самообслуживания. Меню самообслуживания — это набор команд, которые ваш клиент может выбрать в мессенджере для получения заранее заданных ответов. В мессенджерах, поддерживающих кнопки, меню можно показывать с их помощью. См. раздел *«Настройки» \> «Меню самообслуживания»* на сайте).

##### **Параметры тела**

Пример:

{ "channel\_id": 57270 }

* Channel\_id — (необязательный) идентификатор канала. Меню самообслуживания различно для каждого канала.

Некоторые поля в результатах:

* команда – быстрая команда клиенту для вызова данного пункта меню из мессенджера.  
* ParentID – идентификатор родительского пункта меню. Если текущий элемент меню является корневым, возвращается *значение null .*  
* позиция – позиция текущего пункта меню на его уровне.  
* уровень – уровень текущего пункта меню.  
* url – URL-адрес для звонка, когда клиент выбирает этот пункт меню.  
* url\_enabled – если равно 1, система отправит обратно клиенту текстовый ответ, который возвращает указанный выше URL.  
* Assign\_id – если не *null* , то чат с клиентом будет закреплен за указанным оператором (если еще не назначен).  
* изображение – ссылка на изображение или PDF-файл, которая отправляется при выборе этого пункта меню.  
* tags – массив тегов, которые можно назначить или удалить из клиента и запросить при выборе этого пункта меню. См. раздел *«Настройки» \> «Меню самообслуживания»* на сайте.  
* smart\_method\_name — имя нашего встроенного Python-скрипта, который будет вызываться, когда клиент выбирает этот пункт меню. В скрипте эта функция должна находиться внутри класса *Handler* и иметь такие аргументы: self, input\_data, c2d. Имя функции в скрипте должно быть таким, как указано здесь, плюс «\_handler» в конце. Пример: *def macro\_call\_handler(self, input\_data, c2d)* .
